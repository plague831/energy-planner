# Модель задачі та метод

Цей файл описує, що саме рахує ядро (`core/`). Він потрібен як основа для розділів 2–3 пояснювальної записки.

## 1. Дискретизація часу

Доба ділиться на T = 96 інтервалів (слотів) по Δ = 15 хв. Усі величини вважаються сталими в межах слоту.

## 2. Вхідні дані

- **Мережа:** g_t ∈ {0, 1} — наявність світла в слоті t за графіком; P_grid — ліміт потужності вводу, Вт.
- **Зарядна станція:** ємність E_max, початковий заряд E_0, мінімально допустимий заряд E_min, бажаний заряд на кінець доби E_target (Вт·год); потужність заряджання P_ch і інвертора P_inv (Вт); ККД заряджання η_ch і розряджання η_dis.
- **Постійні навантаження j:** потужність P_j, пріоритет w_j ∈ {1..5}, години роботи (маска a_jt).
- **Прилади зі зсувним часом i:** потужність P_i, тривалість d_i слотів, вікно [e_i, l_i] (не раніше / закінчити до), бажаний старт p_i, пріоритет w_i, ознака «можна живити від станції».

## 3. Змінні рішення

Для кожного приладу обирається слот запуску s_i ∈ {e_i, …, l_i − d_i} або s_i = −1 (не вмикати сьогодні). Прилад працює без перерви d_i слотів.

Заряджання станції задається правилом: коли є світло, станція заряджається з максимально можливою потужністю min(P_ch, P_grid − навантаження, вільна ємність).

## 4. Імітація доби

Для кожного слоту t:

1. Доступна потужність: P_grid, якщо світло є; інакше min(P_inv, (E_t − E_min)·η_dis / Δ), якщо є станція; інакше 0.
2. Навантаження обслуговуються в порядку спадання пріоритету, поки вистачає доступної потужності.
3. Постійне навантаження, якому не вистачило потужності, вимикається на цей слот.
4. Прилад, якому не вистачило потужності (або який не можна живити від станції під час відключення), вважається перерваним: його цикл зіпсовано, далі він не працює.
5. Заряд станції оновлюється з урахуванням ККД.

## 5. Цільова функція (штраф, мінімізується)

J = c₁·Σ w_j·(години вимкнення j) + c₂·Σ w_i·[прилад i не відпрацював] + c₃·Σ w_i·|s_i − p_i|·Δ + c₄·max(0, E_target − E_T)/E_max

Коефіцієнти за замовчуванням: c₁ = 1, c₂ = 10, c₃ = 0.3, c₄ = 20 (`DEFAULT_WEIGHTS` у `core/src/simulate.js`).

## 6. Модель невизначеності графіка

Фактичний графік ω генерується з запланованого:

- початок і кінець кожного відключення зсуваються на δ ~ N(0, σ²), обмежене ±δ_max (за замовчуванням σ = 30 хв, δ_max = 90 хв);
- заплановане відключення може не відбутися з ймовірністю p_cancel (0.05);
- з ймовірністю p_extra (0.1) за добу виникає позапланове відключення тривалістю 1–3 год.

## 7. Стійкий критерій (наукова новизна)

Замість штрафу за одним (запланованим) графіком план оцінюється на множині з N сценаріїв ω₁…ω_N:

F(s) = mean_k J(s, ω_k) + λ·CVaR_α(J(s, ω))

де CVaR_α — середній штраф серед (1 − α)·N найгірших сценаріїв (α = 0.9, λ = 0.5). Перший доданок відповідає за середню якість плану, другий — за ризик у найгірших випадках.

Для навчання методу використовується одна множина сценаріїв (N = 60, зерно 1001), а для перевірки — інша (300–500 сценаріїв, інше зерно), тому оцінка не завищена.

## 8. Методи, що порівнюються

| Метод | Що робить |
|---|---|
| `naive` | Прилади вмикаються в бажаний час (як без сервісу) |
| `greedy` | Прилади розставляються по черзі за пріоритетом, кожному обирається найкращий час за графіком |
| `ga` | Генетичний алгоритм, цільова функція — штраф за запланованим графіком |
| `robust-ga` | Генетичний алгоритм зі стійким критерієм F(s) на множині сценаріїв (запропонований метод) |

Параметри ГА: популяція 40, до 120 поколінь, зупинка після 30 поколінь без покращення, турнірний відбір (k = 3), рівномірне схрещування (0.9), мутація гена з ймовірністю 1/n (зсув на 1–4 слоти, новий випадковий старт або «не вмикати»), елітизм 2. Початкова популяція містить рішення `naive` і `greedy`.

## 9. Перші результати (демонстраційна квартира, середня невизначеність, 500 тестових сценаріїв)

| Метод | Середній штраф | CVaR 90% | P(прилад не відпрацював) | P(вимкнення постійних навантажень) |
|---|---|---|---|---|
| naive | 125.7 | 173.9 | 99.2% | 92.6% |
| greedy | 50.3 | 132.1 | 76.2% | 35.6% |
| ga | 50.3 | 132.1 | 76.2% | 35.6% |
| robust-ga | 14.3 | 44.0 | 7.0% | 2.0% |

Повна таблиця для чотирьох типів домогосподарств і трьох рівнів невизначеності: `npm run experiment`.

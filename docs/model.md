# Модель задачі та метод

Цей файл описує, що саме рахує ядро (`core/`). Він потрібен як основа для розділів 2–3 пояснювальної записки.

## 1. Дискретизація часу

Доба ділиться на T = 96 інтервалів (слотів) по Δ = 15 хв. Усі величини вважаються сталими в межах слоту.

## 2. Вхідні дані

- **Мережа:** g_t ∈ {0, 1} — наявність світла в слоті t за графіком; P_grid — ліміт потужності вводу, Вт.
- **Зарядна станція:** ємність E_max, початковий заряд E_0, мінімально допустимий заряд E_min, бажаний заряд на кінець доби E_target (Вт·год); потужність заряджання P_ch і інвертора P_inv (Вт); ККД заряджання η_ch і розряджання η_dis.
- **Постійні навантаження j:** потужність P_j, пріоритет w_j ∈ {1..5}, години роботи (маска a_jt).
- **Прилади зі зсувним часом i:** потужність P_i, тривалість d_i слотів, вікно [e_i, l_i] (не раніше / закінчити до), бажаний старт p_i, пріоритет w_i, ознака «можна живити від станції».

## 3. Змінні рішення

Для кожного приладу обирається слот запуску s_i ∈ {e_i, …, l_i − d_i} або s_i = −1 (не вмикати сьогодні). Прилад працює без перерви d_i слотів.

Заряджання станції задається правилом: коли є світло, станція заряджається з максимально можливою потужністю min(P_ch, P_grid − навантаження, вільна ємність).

## 4. Імітація доби

Для кожного слоту t:

1. Доступна потужність: P_grid, якщо світло є; інакше min(P_inv, (E_t − E_min)·η_dis / Δ), якщо є станція; інакше 0.
2. Навантаження обслуговуються в порядку спадання пріоритету, поки вистачає доступної потужності.
3. Постійне навантаження, якому не вистачило потужності, вимикається на цей слот.
4. Прилад, якому не вистачило потужності (або який не можна живити від станції під час відключення), вважається перерваним: його цикл зіпсовано, далі він не працює.
5. Заряд станції оновлюється з урахуванням ККД.

## 5. Цільова функція (штраф, мінімізується)

J = c₁·Σ w_j·(години вимкнення j) + c₂·Σ w_i·[прилад i не відпрацював] + c₃·Σ w_i·|s_i − p_i|·Δ + c₄·max(0, E_target − E_T)/E_max

Коефіцієнти за замовчуванням: c₁ = 1, c₂ = 10, c₃ = 0.3, c₄ = 20 (`DEFAULT_WEIGHTS` у `core/src/simulate.js`).

## 6. Модель невизначеності графіка

Фактичний графік ω генерується з запланованого:

- початок і кінець кожного відключення зсуваються на δ ~ N(0, σ²), обмежене ±δ_max (за замовчуванням σ = 30 хв, δ_max = 90 хв);
- заплановане відключення може не відбутися з ймовірністю p_cancel (0.05);
- з ймовірністю p_extra (0.1) за добу виникає позапланове відключення тривалістю 1–3 год.

## 7. Стійкий критерій (наукова новизна)

Замість штрафу за одним (запланованим) графіком план оцінюється на множині з N сценаріїв ω₁…ω_N:

F(s) = mean_k J(s, ω_k) + λ·CVaR_α(J(s, ω))

де CVaR_α — середній штраф серед (1 − α)·N найгірших сценаріїв (α = 0.9, λ = 0.5). Перший доданок відповідає за середню якість плану, другий — за ризик у найгірших випадках.

Для навчання методу використовується одна множина сценаріїв (N = 60, зерно 1001), а для перевірки — інша (300–500 сценаріїв, інше зерно), тому оцінка не завищена.

## 8. Методи, що порівнюються

| Метод | Що робить |
|---|---|
| `naive` | Прилади вмикаються в бажаний час (як без сервісу) |
| `greedy` | Прилади розставляються по черзі за пріоритетом, кожному обирається найкращий час за графіком |
| `ga` | Генетичний алгоритм, цільова функція — штраф за запланованим графіком |
| `robust-ga` | Генетичний алгоритм зі стійким критерієм F(s) на множині сценаріїв (запропонований метод) |

Параметри ГА: популяція 40, до 120 поколінь, зупинка після 30 поколінь без покращення, турнірний відбір (k = 3), рівномірне схрещування (0.9), мутація гена з ймовірністю 1/n (зсув на 1–4 слоти, новий випадковий старт або «не вмикати»), елітизм 2. Початкова популяція містить рішення `naive` і `greedy`.

## 10. Кілька джерел живлення

Домогосподарство може мати кілька джерел (`household.sources`): зарядні станції, генератори, сонячні панелі.

- **Станції.** Для планування зводяться в одну еквівалентну: ємності, потужності заряджання й інвертора додаються, заряд — середньозважений за ємністю.
- **Генератор g:** номінальна потужність P_g, час роботи повного бака t₅₀ при навантаженні 50%, рівень пального f_g ∈ [0, 1]. Витрата пального за слот при навантаженні x = P_out / P_g наближено лінійна: Δf = (Δ / t₅₀) · q(x) / q(0.5), де q(x) = 0.25 + 0.75·x (на холостому ходу генератор витрачає близько чверті номінальної витрати).
- **Сонячні панелі:** генерація S_t — синусоїда між сходом і заходом сонця (за замовчуванням 07:00–18:00), площа під якою дорівнює денній енергії P_peak · H_sun · 0.75; потужність не перевищує 0.75 · P_peak.

### Керування генератором

Генератор працює лише під час відключення за правилом із порогом θ: вмикається, коли заряд станції падає до θ, і вимикається, коли станція підзарядилась до θ + 30% (гістерезис), пальне скінчилось або повернулося світло. Без станції генератор вмикається з початку відключення. Поріг θ ∈ {0%, 5%, …, 100%} або «не вмикати» — додатковий ген хромосоми, тож ГА оптимізує його разом із часом запуску приладів. Правило реагує на фактичний стан станції, тому залишається коректним, коли відключення зсувається.

### Імітація слоту з кількома джерелами

1. Доступна потужність: P_grid (якщо світло є) + S_t + Σ P_g (працюючі генератори) + потужність станції під час відключення.
2. Потужні прилади, які не можна живити від станції, дозволені, якщо є мережа або працює генератор.
3. Енергобаланс: спершу сонце, потім мережа або генератор, станція покриває решту під час відключення і заряджається з надлишку (не більше P_ch).

До цільової функції додається доданок c₅ · (витрачена частка бака), c₅ = 8 (`generatorFuel`): пальне, шум і знос.

## 11. Перепланування протягом дня

Оператор змінює опублікований графік протягом дня. План на сьогодні будується з поточного моменту τ:

- прилади, які вже ввімкнулися до τ, фіксуються на своєму часі (їхні гени не змінюються);
- решта приладів може стартувати не раніше τ; прилад, вікно якого минуло, вважається пропущеним і не штрафується;
- початковий заряд станції і рівень пального — фактичні на момент τ (з попереднього розрахунку або введені людиною);
- імітація і сценарії невизначеності охоплюють лише слоти t ≥ τ.

На сайті графік перевіряється кожні 10 хвилин; якщо він змінився, план на решту дня перебудовується, а людина бачить, які прилади перенесено.

## 12. Результати для розширень

`npm run experiment:multisource` порівнює правила керування генератором з оптимізованим порогом і план без перепланування з перебудованим після зміни графіка. Таблиці — у `core/experiments/multisource-report.md`.

## 13. Порівняння з точним розв'язком (MILP)

Задача на опублікованому графіку записана як задача змішаного цілочисельного лінійного програмування (`core/src/milp.js`) і розв'язується солвером HiGHS:

- бінарні x_{i,s} — прилад i стартує в слоті s, z_i — не вмикати; Σ_s x_{i,s} + z_i = 1;
- бінарні b_{j,t} — постійне навантаження j увімкнене в слоті t;
- неперервні c_t (заряджання, коли є світло) і E_t (енергія станції) з балансом E_{t+1} = E_t + η_ch·c_t·Δ (світло є) або E_{t+1} = E_t − L_t·Δ/η_dis (відключення), E_min ≤ E_t ≤ E_max;
- обмеження потужності вводу (L_t + c_t ≤ P_grid) та інвертора (L_t ≤ P_inv);
- цільова функція — той самий штраф J, що й в імітаторі.

На відміну від імітатора, солвер може обирати заряджання і вимкнення постійних навантажень оптимально, тож його значення — нижня оцінка штрафу. `npm run experiment:milp` показує, що ГА досягає цієї оцінки (тобто знаходить доведений оптимум) на всіх тестових задачах, але навіть доведений оптимум за графіком значно гірший за стійкий план, коли відключення зсуваються. Таблиці — у `core/experiments/milp-report.md`.
